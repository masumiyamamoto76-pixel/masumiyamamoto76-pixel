# 山本ますみ / Masumi Yamamoto

> 自動化の敵は「作れないこと」ではなく、**壊れたことに誰も気づかないこと**。

事業会社でマーケティング統括をしています。日次・週次・月次のレポートを人手ゼロで回す仕組みを複数、本番で運用してきました。
ここでは、その型を汎用化して「動くコード全文＋実測ログ」で公開しています。掲載する例はすべて架空データです。

## やっていること

| 柱 | 中身 |
|---|---|
| **無人運用** | スケジューラでの定期実行、失敗検知、自己点検。「動いているつもり」を作らない |
| **品質ガバナンス** | 出力を機械で検算し、検算に落ちたら**そもそも送らない**出荷ゲート。書くAIと裁くAIを分ける多段構成 |
| **効果測定** | 母数の定義から先に決める。before/after の工数を実測して数字で報告する |

自動化は必ず静かに壊れます。入力CSVの列名が変わる、ファイルが来ない、権限が切れる——
そして**エラーを出さないまま、中身の欠けたレポートが配られ続ける**。
本体とは別に「見張り役」を置き、異常時だけ通知する。作って終わりにしないための設計を書いています。

## お受けしている相談

手作業の集計・転記・報告が、担当者の時間を毎週奪っている——という状態を、仕組みで終わらせる仕事をしています。
お受けしているのは次の3つです。

**1. 定期集計・レポートの自動化**
毎朝/毎週/毎月の手集計を、無人で回る処理に置き換えます。単に自動化するだけでなく、**出力の検算**（内訳の合計＝全体の突合、分類の全数チェック）と**見張り役**（成果物の鮮度・中身を毎日検査し、異常時のみ通知）を必ずセットで納品します。運用手順書つき。

**2. 「作ったが壊れた」自動化の復旧＋監視の付け直し**
前任者が作って動かなくなったスクリプト、仕様変更で黙って壊れた処理の復旧。原因を特定して直したうえで、**同じことが次に起きたら気づける状態**にして返します。「直して終わり」にしません。

**3. 現状診断（1〜2時間）**
「どの業務が自動化に向いているのか分からない」段階の相談。対象業務の洗い出し・現状工数・自動化の可否・概算の見積を1〜2枚の診断書にしてお渡しします。
